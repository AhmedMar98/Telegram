# دليل التشغيل — ماذا تفعل حين يتعطّل شيء

المرحلة ١٠. البنود ١٨٢ و١٨٤ و١٨٨ و١٩٣ و١٩٤ و١٩٥ كلها إجراءات لا كود،
وتجميعها في ملف واحد هو الشكل الوحيد المفيد لها: من يبحث عنها يبحث وقت
العطل، لا وقت الهدوء.

---

## ١. من يلاحظ العطل، وكيف (الفكرة ١٨٤)

| العطل | من يبلّغ | خلال |
|---|---|---|
| فشل CI على PR | GitHub نفسه (بريد + علامة على الـPR) | دقائق |
| فشل تشغيلة مجدولة | GitHub (بريد فشل Actions) **و** لوحة «حالة النظام» | ساعة |
| توقّف الجمع كلّياً | تنبيه البوت (`collector_failed`، مفعَّل افتراضاً) | التشغيلة نفسها |
| اقتراب حدّ التخزين | تنبيه البوت (`storage_high`) | شهرياً أو عند الفحص |
| توقّف الخدمة نفسها | اختبار الدخان (`smoke.yml`) كل ٦ ساعات | ٦ ساعات |
| توقّف الخدمة، خارجياً | UptimeRobot إن ضُبط (§٢) | ٥ دقائق |

**الفجوة المعترف بها:** لا شيء ممّا سبق يعمل إن تعطّلت GitHub Actions نفسها.
هذا ما تعالجه §٥.

## ٢. مراقبة خارجية مجانية (الفكرة ١٨٢)

UptimeRobot مجاني لخمسين فحصاً بفاصل خمس دقائق، ولا يحتاج استضافة ذاتية:

1. أنشئ حساباً على uptimerobot.com
2. Add New Monitor ← HTTP(s)
3. الرابط: `https://<your-app>/healthz`
4. الفاصل: ٥ دقائق

**اضبطه على `/healthz` لا `/readyz`**: الأول لا يلمس قاعدة البيانات عمداً،
فانقطاع عابر في القاعدة لا يُنتج تنبيهاً كاذباً بأن الخدمة ساقطة.

**توقّع فشلاً أولياً كاذباً بعد الخمول:** الخطة المجانية تنام، وأول طلب بعدها
قد يتأخّر نحو دقيقة. اضبط مهلة المراقب على ٣٠ ثانية على الأقل.

هذه إعدادات لا كود — لا شيء في هذا المستودع يعتمد عليها، ولا يكسر بغيابها.

## ٣. توقّف كامل للخدمة (الفكرة ١٨٨)

بالترتيب، وأوقفْ عند أول ما ينجح:

1. **هل الخدمة نائمة فقط؟** افتح الرابط وانتظر دقيقة. الخطة المجانية تنام
   بعد ١٥ دقيقة خمول — وهذا ليس عطلاً.
2. **`/healthz`؟** إن ردّ 200 فالعملية حيّة والمشكلة أضيق: جرّب `/readyz`.
3. **`/readyz` يعيد 503؟** قاعدة البيانات هي المشكلة. افحص لوحة Render:
   هل انتهت مدة قاعدة البيانات المجانية؟ (§٤ للاستعادة.)
4. **آخر نشر؟** لوحة التحكم ← تذييل الصفحة يعرض SHA النشر الحيّ. قارنه
   بآخر دمج في `main`: إن اختلفا فالنشر عالق أو فشل.
5. **آخر تشغيلة مجدولة؟** لوحة «حالة النظام» تعرض آخر نتيجة لكل تشغيلة.
6. **تراجُع:** في Render، Deploys ← اختر نشراً سابقاً ناجحاً ← Redeploy.
   لا حاجة لتغيير الكود لتنفيذ التراجع.

**ما لا تفعله:** لا تحذف قاعدة البيانات لتجرّب «بداية نظيفة». النسخ
الاحتياطي أسبوعي، فقد تخسر حتى سبعة أيام.

## ٤. الاستعادة من نسخة احتياطية

النسخ في GitHub Actions artifacts (تبقى ٣٥ يوماً):

```bash
# نزّل آخر artifact من صفحة تشغيل "Weekly DB backup"، ثم:
pg_restore --clean --if-exists --no-owner -d "$DATABASE_URL" backup.dump
```

## ٥. إن تعطّلت GitHub Actions أو ضاعت الأسرار (الفكرة ١٩٣)

كل الجدولة في هذا المشروع تعتمد على GitHub Actions — وهي نقطة فشل واحدة
معترف بها، لا مخفيّة. البدائل، بلا تكلفة:

| الحالة | البديل |
|---|---|
| Actions معطّلة مؤقّتاً | شغّل السكربتات يدوياً: `python scripts/collect.py` وغيرها تعمل من أي جهاز فيه `DATABASE_URL` |
| الأسرار حُذفت | كلها قابلة لإعادة التوليد: `TG_SESSION_STRING` عبر `scripts/make_session_string.py`، ومفتاح API من اللوحة، و`BOT_TOKEN` من BotFather |
| **`FIELD_ENCRYPTION_KEY` ضاع** | **لا استعادة.** سلاسل جلسات تيليجرام المشفَّرة به تصير غير قابلة للفكّ إلى الأبد. الحلّ الوحيد إعادة تفويض حسابات الجمع من الصفر. احتفظ بنسخة منه خارج GitHub |
| المستودع نفسه ضاع | القاعدة مستقلّة عنه؛ الكود مفتوح ويمكن استنساخه من أي نسخة محلية |

**الفكرة ١٩٣ تحديداً:** لا يوجد بديل مجدول تلقائي للنسخ الاحتياطي — أي أن
تعطّل Actions لأسابيع يعني توقّف النسخ. البديل الموثّق هو التشغيل اليدوي
أعلاه، وهذا حدّ حقيقي لا يُخفى.

## ٦. اختبار استعادة دوري (الفكرة ١٩٤)

**نسخة احتياطية لم تُختبر استعادتها ليست نسخة احتياطية.** كل ثلاثة أشهر:

```bash
createdb restore_test
pg_restore --no-owner -d "postgresql://.../restore_test" backup.dump
psql -d restore_test -c "select count(*) from links;"   # يطابق التوقّع؟
psql -d restore_test -c "select version_num from alembic_version;"
dropdb restore_test
```

يُنفَّذ يدوياً عمداً: أتمتته تعني منح تشغيلة مجدولة صلاحية إنشاء قواعد
بيانات، وهي صلاحية أوسع بكثير ممّا يحتاجه أي شيء آخر هنا.

## ٧. متى يستحقّ التفكير بمغادرة الطبقة المجانية (الفكرة ١٩٥)

مؤشّرات ملموسة لا انطباعات. **لا شيء منها متحقّق اليوم:**

| المؤشّر | العتبة | القياس |
|---|---|---|
| حجم القاعدة | > ٨٠٪ من `STORAGE_LIMIT_BYTES` | تنبيه `storage_high` |
| زمن الاستجابة | p95 > ١٠٠٠ms باستمرار | لوحة «حالة النظام» |
| النوم يؤذي فعلاً | إن صار تأخّر الدقيقة بعد الخمول يمنع استخداماً حقيقياً | ملاحظة المستخدم |
| دقائق Actions | > ٨٠٪ من الحصّة الشهرية | صفحة الفوترة في GitHub |
| عمر القاعدة | اقتراب انتهاء مدة قاعدة Render المجانية | لوحة Render |

**والأصدق:** أول مؤشّر يتحقّق غالباً هو الأخير، وهو ليس مشكلة أداء بل قرار
منصّة. بدائل Postgres المجانية موثّقة في `docs/14-postgres-alternatives.md`.
